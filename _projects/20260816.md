The general consensus online is that running local models has become trivial. That is certainly true if the goal is running a single-user `cli` wrapper like `ollama run` in a terminal window. However, that abstraction falls apart the moment one need dynamic batching, heterogenous multi-model execution, optimized GPU memory lifecycle management, or the ability to manage host CUDA drivers predictably without breaking local virtual environments.

Rather than dirtying the host `os` with ad-hoc `python` scripts or standard homelab setups (I am not interested in running a media server), I began building a local `k3s` environment leveraging NVIDIA Triton Inference Server with `vLLM` and `ONNX` Runtime backends. The goal is to establish a local edge execution environment that mirrors the exact containerized patterns, declarative configurations, and model registry topologies required for production deployments on Amazon `EKS`.

**Summary of execution steps & milestones**

**Step 1: Base `k3s` Infrastructure & GPU Passthrough Setup**

- Provision a single-node `k3s` cluster on the host system.

- Configure `containerd` (`/etc/containerd/config.toml`) to utilize `nvidia-container-runtime`.

- Register `runtimeClassName`: `nvidia` within `k3s` and verify `GPU` passthrough via [nvidia.com/gpu](https://nvidia.com/gpu) device limits.

**Step 2: Pod Shared Memory & Storage Architecture**

- Configure Kubernetes pod specs to mount `emptyDir` with medium: Memory to `/dev/shm` to support high-throughput IPC for PyTorch and ONNX worker processes.

- Set up host path mounts for local model weight storage (`/opt/model_repository`) to mimic a remote bucket structure.

**Step 3: Multi-Backend Triton Configuration**

- Build declarative `config.pbtxt` definitions for ONNX Runtime models (`bge_small_embedding`, `resnet50_visio`n) enabling dynamic batching (max_queue_delay_microseconds: 5000).

- Configure the `vLLM C++` backend for sequence generation (`qwen_1b`) leveraging PagedAttention and continuous batching.

**Step 4: Explicit Memory Isolation & Dynamic Model Control**

- Launch Triton with `--model-control-mode=explicit` to prevent vLLM from pre-allocating GPU VRAM at container initialization.

- Validate static loading of lightweight ONNX models on server startup (`~1.8 GB` VRAM footprint).

- Test dynamic loading and unloading of LLM weights via REST API endpoints (`POST /v2/repository/models/qwen_1b/load` and `/unload`) to manage VRAM allocation cleanly.

**Step 5: External Routing & Ingress Verification**

- Expose Triton ports via a NodePort service mapping host ports `30800` (`HTTP`), `30801` (`gRPC`), and `30802` (`Prometheus Metrics`).

- Perform streaming inference and embedding requests via standard HTTP/gRPC clients to confirm low-latency routing directly into the cluster.

_Configure Persistent Containerd NVIDIA Runtime:_

```bash 
  sudo mkdir -p /var/lib/rancher/k3s/agent/kubelet/device-plugins
  sudo mkdir -p /var/lib/kubelet
  sudo rm -rf /var/lib/kubelet/device-plugins
  sudo ln -s /var/lib/rancher/k3s/agent/kubelet/device-plugins /var/lib/kubelet/device-plugins

  sudo bash -c 'cat << "EOF" > /var/lib/rancher/k3s/agent/etc/containerd/config.toml.tmpl
  version = 2

  [plugins."io.containerd.grpc.v1.cri"]
    enable_selinux = false
    stream_server_address = "127.0.0.1"
    stream_server_port = "10010"

  [plugins."io.containerd.grpc.v1.cri".containerd]
    default_runtime_name = "nvidia"
    snapshotter = "overlayfs"

    [plugins."io.containerd.grpc.v1.cri".containerd.runtimes.runc]
      runtime_type = "io.containerd.runc.v2"

    [plugins."io.containerd.grpc.v1.cri".containerd.runtimes.nvidia]
      runtime_type = "io.containerd.runc.v2"
      [plugins."io.containerd.grpc.v1.cri".containerd.runtimes.nvidia.options]
        BinaryName = "/usr/bin/nvidia-container-runtime"
  EOF'

  sudo nvidia-ctk runtime configure --runtime=containerd \
    --config=/var/lib/rancher/k3s/agent/etc/containerd/config.toml.tmpl \
    --set-as-default

  sudo systemctl restart k3s
```

**Compilation Script** (`scripts/compile_configs.py`)

```bash
#!/usr/bin/env python3
import os
import yaml
from jinja2 import Environment, FileSystemLoader

def compile_triton_configs():
    catalog_path = "model_catalog.yaml"
    if not os.path.exists(catalog_path):
        raise FileNotFoundError(f"Missing catalog at {catalog_path}")

    with open(catalog_path, "r") as f:
        data = yaml.safe_load(f)

    env = Environment(loader=FileSystemLoader("templates"))
    template = env.get_template("config.pbtxt.j2")

    for model_cfg in data.get("models", []):
        model_name = model_cfg["model_name"]
        target_dir = os.path.join("model_repository", model_name)
        os.makedirs(os.path.join(target_dir, "1"), exist_ok=True)

        rendered_pbtxt = template.render(**model_cfg)
        output_file = os.path.join(target_dir, "config.pbtxt")

        with open(output_file, "w") as f:
            f.write(rendered_pbtxt)

        print(f"--> [Compiled] {output_file}")

if __name__ == "__main__":
    compile_triton_configs()
```

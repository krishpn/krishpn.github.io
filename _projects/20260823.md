**Configure GPU Access on Bare-Metal K3s**

GPU pass-through on single-node Kubernetes clusters often fails due to path mismatches between Kubelet, Containerd, and CNI plugins. K3s stores CNI files and device plugin sockets in non-standard paths instead of standard system locations like `/etc/cni/net.d`. Symlinking the K3s agent directory to standard Linux paths fixes network initialization hangs during pod creation.

Updating the Containerd runtime template to use nvidia-container-runtime forces the CRI plugin to mount GPU device nodes (`/dev/nvidia*`) directly into requested pod namespaces. Once applied, the node reports [nvidia.com/gpu](https://nvidia.com/gpu) capacity directly to the scheduler.

**Fix Container IPC and Manage VRAM**

Running multiple backends on an `8GB` GPU causes two problems: PyTorch worker crashes from container memory caps, and CUDA Out-Of-Memory errors from competing model allocations. Default container runtimes cap shared memory (`/dev/shm`) at 64MB, causing IPC failures between PyTorch processes. Mounting a RAM-backed emptyDir volume to `/dev/shm` in the pod spec fixes these worker crashes.

To manage VRAM, Triton starts with `--model-control-mode=explicit` to stop models from loading automatically. Instead, `HTTP API` calls (`POST /v2/repository/models/<model>/load`) swap models in and out of GPU memory on demand.
